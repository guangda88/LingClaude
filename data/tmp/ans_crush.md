**一、最值得注意的 2-3 个设计趋势**

1. **凭证与权限的对象化、结构化**。Muse 的 Sentinel 网关（模型看不到真实密码）、Dots 的动作四档策略（自动/预审批/先问/交还人）、DSH 的调用前同模型审查，共同指向一点：权限不再是 prompt 里的自然语言约定，而是策略对象+执行网关。原因很现实：prompt 级约束在对抗场景下不可靠，只有网关层（模型拿不到明文、动作分类路由、调用前机器审查）才能保证"模型想作恶也做不了"。

2. **常驻实体+独立执行环境**。Grok Bot 的 Bot 名册、Cue 的每 agent 独立 email/phone/wallet/电脑、Muse 的专属 VM，本质是把 agent 从"一次性会话"升级为"有身份、有财产、有边界的责任实体"。这决定了审计、追责、爆炸半径隔离都有了物理锚点——没有独立环境，权限分层就是纸面设计。

3. **编排层弃 stdout 包装转 SDK**。stdout 解析脆弱、无类型、无法流式增量，SDK 化意味着 agent 行为可被结构化消费，为上面两条（策略路由、审计）提供机器可读的输入。这是基础设施层面的必要条件，不是风格偏好。

**二、lc 最值得借鉴的 3 个进化方向**

1. **把"动作分级路由"做成网关代码，而非守卫文档**。lc 已有守卫 H1-H17、PreToolUse hook（发送三验已 hook 化），可以直接落地 Dots 四档制：给每个工具/命令定义 risk_level（read-only / reversible-write / external-send / destructive），在 PreToolUse hook 里查表路由——L0 自动放行、L1 预审批白名单（如已验证的发送三验）、L2 先问用户、L3 拒绝并要求人工。这比"建议-执行强制分离"这条自然语言规则可靠一个数量级，且 lc 已有 hook 基础设施，改造成本低。具体做法：在 crush.json 的 hook 配置里加一个 risk_table.json，hook 读表决策，决策结果写审计台账。

2. **凭证分层：模型永不见明文**。lc 作为多成员家族，各成员调外部 API（Laya/system_one）的密钥应走"凭证代管"：模型只持有凭证句柄（如 `cred:laya_api`），实际注入由 harness 层在请求出口处完成。可用一个本地 secret proxy（lc 已有 8765 proxy3 的经验）实现：模型发请求带句柄，proxy 替换为真实凭证后转发，审计台账记录句柄级调用而非明文。这直接堵住"日志/上下文泄漏密钥"这一自托管 agent 最常见事故。

3. **记忆可携可纠正的结构化落地**。lc 有 journals 和灵忆 lm_query，但缺"可纠正"机制。借鉴 Muse/Dots：给每条记忆记录加 `confidence` + `last_verified` + `source_evidence` 三字段，守卫触发时（如 H17 闭环申报）自动降权未验证记忆；提供 `lm_correct(record_id, correction)` 接口，纠正不删除原记录而是追加版本链。lc 已有验证台账纪律，把这纪律从"自觉标注三级推导"变成 schema 强制字段即可。

**三、陷阱与被高估的趋势**

1. **"每次工具调用前同模型先审"（DSH 的自动授权审查）——被高估**。同模型自审存在共谋失效：审查模型与被审模型共享同一套幻觉模式，且延迟翻倍、成本翻倍。对 lc 而言，规则表+hook 的确定性检查（上文方向1）比"再问一次模型"既便宜又可靠。模型审查只该用于规则表覆盖不了的长尾场景，不能当主防线。

2. **每 agent 独立 email/phone/wallet（Cue 式全套身份）——lc 不应跟风**。这是面向 C 端"agent 替你活在互联网上"的产品形态，对 lc 这种工程执行型家族是过度建设：独立钱包引入资产管理风险，独立 phone/email 引入账号运维负担，而收益（对外身份）在代码审计场景几乎为零。lc 需要的是**环境隔离**（已有家族成员边界可强化为容器级隔离），不是**社会身份**。

3. **"常驻+空闲时主动调研"（Dots 式主动行为）——谨慎对待**。lc 已有 SDT 自驱任务和"go on≠自驱授权"的治理教训，主动行为是自托管 agent 最大的偏航源（无人纠偏时的目标漂移、资源空转）。正确姿势是保留 cron/webhook **显式触发**（lc 已有），不做模型自主发起的空闲探索。主动性应由调度器驱动，不应由模型驱动。

核心判断：这一轮的实质进步在"治理的工程化"（权限对象、凭证分层、结构化编排），而非"agent 更像人"（身份、钱包、主动性）。lc 的既有优势（铁律+台账+hook）恰好站在正确一侧，应把自然语言规则继续下沉为网关代码，而不是追逐 C 端拟人形态。
