# TUI 输入/输出工程调研邀请（统一提示词）

你是终端 TUI 工程顾问。请基于你自己所属 CLI 工具的真实实现机制与你的工程经验，回答以下问题。重点考察「终端输入管线」与「输出滚动/重绘」的通用工程方案。请给出具体、可落地的机制建议（键位处理、转义序列、线程模型、缓冲策略、prompt_toolkit/termios 层面的具体做法），不要泛泛而谈。

背景：我们在用 Python prompt_toolkit 3.x 维护一个全屏 REPL TUI（底部输入框 + 可滚动输出窗 HSplit 布局），遇到以下问题：

1. 流式生成输出向上滚动时，用户正在输入的内容会被冲乱（输入行内容与输出交错、错位）。
2. 粘贴文本后提交，内容前后会多出多余字符串（疑似 bracketed paste 标记 \\x1b[200~ / \\x1b[201~ 泄漏）。
3. 粘贴/输入多行文字时被截断或被分段、分行提交给 LLM（应当整块提交）。
4. 流式生成结束时，用户输入有时被吞掉，回车后无响应，需要重新输入一遍。
5. 方向键被转换成字面字符（如 ^[[A、[27u）显示在输入行，无法移动光标，也无法用上箭头唤起输入历史（怀疑 kitty keyboard protocol / focus reporting / mouse reporting 残留模式）。
6. 移动光标时输入行出现一串串转义位置码噪声（疑似 CSI 序列被当作正文插入）。
7. 无法用 PageUp/PageDown 或鼠标滚轮查看会话历史；退出 TUI 后还想查看历史也无入口。

请按以下格式回答：
## 问题 N：<标题>
- 根因分析（终端层/prompt_toolkit 层/线程层）
- 推荐方案（具体机制，含关键 API 或转义序列名）
- 我们工具中对应的实现要点（如果你能访问自身实现知识）
- 优先级评估（P0/P1/P2）

最后给一节「## 通用架构建议」：对比三种输入架构的优劣：A) 单读者 prompt_toolkit 全接管；B) 应用自管 termios + 自写键序列解析器；C) 混合（PTY + 异步读 + 状态机解析）。说明各自对上述 7 问题的免疫性。
