# 观测层与判定层铁律 Runbook

> 来源：2026-10-07 browse_agg/ai01 排障会话复盘。两次重大误诊（根分区只读、16家假注册）均源于「用被污染的观测通道下诊断」与「用表面成功替代真实成功」。本文件是防复发锁，违反任何一条前先给出书面豁免理由。

## 一、观测层：先问「我从哪看到的」，再问「看到什么」

### 铁律 O1：诊断结论必须区分「我看到的」和「宿主真实状态」

本机 `bash` 工具 = `bwrap --unshare-net --ro-bind /`（1GiB 内存上限）独立沙箱。
以下判断**一律不可以在沙箱内下结论**，必须走 `run_in_background`（沙箱外通道）终审：

| 判断类型 | 沙箱内必然失真的表现 |
|---|---|
| 文件系统可写性 | `/` 整体报只读（EROFS），但宿主一直是 rw |
| 网络连通性 | 127.0.0.1 端口探测永远 refused（unshare-net） |
| 挂载点状态 | /proc/mounts 显示的是沙箱 bind 视图，非宿主挂载表 |
| 常驻进程/端口归属 | 看不到宿主服务的真身 PID/监听口 |
| systemctl/dmesg/journalctl | 部分被安全门拦截或视图受限 |

判别口诀：**极端结论（整盘只读/全端口不通）出现时，先怀疑测量仪器，再怀疑被测对象。**

### 铁律 O2：不许用额外假设拯救矛盾证据

事故还原：沙箱内 touch 报只读，但 Chrome Cookies 文件 mtime 在实时更新。为调和矛盾，曾脑补「ro↔rw 翻转」理论——**当需要发明额外假设来维持一个理论时，优先怀疑理论本身**（奥卡姆剃刀）。正确动作是换通道重测，而不是补假设。

### 铁律 O3：pkill/grep 模式必须防自匹配

`pkill -f browser_agg` 会匹配到**后台作业自己的命令行**（curl .../browser_agg...），自杀 exit -15。两次实战事故。
**标准姿势**：`pkill -f '[c]hrome'`（方括号技巧）；杀进程只准 `kill <精确pid>`，且**动进程前先查 PPID 归属**（上次误杀 systemd 正统实例）。

## 二、判定层：表面成功 ≠ 真实成功

### 铁律 J1：E2E 实测是唯一裁决，DOM 判定只是线索

三个假阳性案例（全部同一天）：

| 案例 | 表面证据 | E2E 裁决 |
|---|---|---|
| deepseek 假注册 | signed_url 分享页有 `[class*=message]` 元素 → 「已登录」 | 回复=页脚「浙ICP备2023025841号」 |
| 元宝游客态 | 游客模式有真实输入框+昵称+头像 → 「已登录」 | 回复=二维码弹窗文字「扫码默认已阅读…」 |
| zhipu 垃圾抓取 | `output_sel` 抓到元素 → 「有回复」 | 内容=客服 SDK 的 Qiankun 容器 HTML |

**规则**：任何「登录态/功能正常」的判定，必须以「真实发一条业务请求 + 校验回复语义」收口。校验回复时要看内容是否语义相关，不能只看非空。

### 铁律 J2：健康端点的 status 字段不可信，要看结构性指标

`/health` 的 `status:ok` 是硬编码，进程活着就 ok。可信的是结构性字段（如 `logged_in` 列表、`persisted` 数量）与内存/磁盘/日志三方交叉验证。

### 铁律 J3：静默失败挖掘——「使用与定义」全文对照法

`LOGGEDIN_FILE`/`SESSION_FILE` 在 766 行文件中被使用但从未定义，`except Exception: pass` 每次吞掉 NameError——登录态持久化从未真正工作过。此类 bug 的通用排查法：**对关键常量做「赋值行搜索」**（`grep -n 'X *=' file`），对 except 块统计吞掉了什么。

## 三、快速自检清单（执行前过一遍）

```
[ ] 这个判断依赖的数据，来自沙箱内还是沙箱外？
[ ] 我是否在用额外假设调和矛盾证据？
[ ] 表面成功（注册成功/有回复/status ok）是否已经过 E2E 语义校验？
[ ] 杀进程是否用了精确 PID + 查过 PPID？
[ ] 关键常量是否确认有定义、except 是否在吞异常？
```
