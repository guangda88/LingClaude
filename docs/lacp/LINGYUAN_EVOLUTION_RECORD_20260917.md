## 一、薄主干·分形插片：优势与代价的完整讨论

**起点问题**：lingclaude"不变的薄主干 + 一切变化皆插片"的架构有何优劣？

### 1.1 优势（当时是推理，后来全部变成实证）

| 论点 | 当日晚些时候的实证 |
|------|-------------------|
| 变化隔离，主干稳定性高 | TOOL 接缝运行时 26 个实现挂载，主干零改动 |
| 可拔插带来测试/运行时红利 | M5 截肢测试：逐级 unregister 主干照跑，L1 替换/L3 缺席可证 |
| 分形递归降低认知负荷 | 每个插片（bash 的 SandboxProvider 等）都是同构的"内核+接缝" |
| 审计可机械化 | J1-J5 → M1-M5 守卫 → arch-guards CI job，三层落地 |

### 1.2 五条代价（当时提出，当日全部被讨论穿透）

1. **间接层税**：走接缝 = Protocol+注册+装配+测试，一次性且无第二实现的变化纯亏；
   深层问题不是"贵"，是**成本错配**（成本即期确定，收益远期概率）+ **接缝棘轮**
   （拆接缝违反铁律 3"主干零 diff"→ 错误接缝只能加不能拆）。
2. **调试链路断裂**：grep 只能找到 Protocol 定义，运行时真相藏在 yaml/manifest/装配 spec；
   真正的痛点是**静态阅读与动态执行的映射断了**，而非栈深本身。
3. **主干"薄"不可度量**：废弃行数判据后没有替代度量→不可度量的规范必然漂移；
   更隐蔽的是**概念变厚**（装配器出现 `if seam_type == ORCHESTRATOR` 特判，行数测不出，
   但主干已与具体插片焊上）。
4. **热拔插承诺无分级**：口头承诺 L2/L3，J2 实际只测 L1（换实现不崩）；
   降级路径本身是"藏在主干里的业务逻辑"（每类接缝加缺席语义，主干知识就厚一层）——
   这是薄主干哲学的**内在极限，不是实现瑕疵**。
5. **僵化风险**：铁律禁止"以后再抽"的临时直连，但没给实验通道；二值（合规/违规）
   缺**违规定价**——缺的不是豁免条款（豁免会被滥用成常规通道），是让"明知故犯"
   可申报、有成本、有期限的债务机制。

**根因收敛**：五条代价里 3 是根（薄不可度量），1/4 是其投影（棘轮=生长无修剪；
拔插无分级=承诺越级），2/5 是症状。**如果只做一件事：给 J5 建守卫，且守卫内容必须是
"知识耦合"与"依赖方向"，不是任何行数代理。**

## 二、"AI 时代的算子革命"：定义落字（立法）

用户定义灵元为"**AI 时代的算子革命**"——该词在灵元语料里原只出现在推理栈语境
（L1 算子拆解），本会话完成概念正名并双落：

- 落点 1：`LINGYUAN_IRON_LAW.md` 开篇（第一性陈述）；
- 落点 2：`灵元V1.0.md` 新增"定义（第一性陈述）"章节（用户署名）。

**定义全文**：以统一数据形态（record）为值域、以封闭算子集合（create/transition/query）
为文法；软件演化从开放式动作约化为封闭动作（新 type/新 state/新插片入册）；
合法操作集合与 Agent 可靠操作集合重合 → 架构对 Agent 原生；一切真相外化为可查询结构
→ 守卫即查询。

**"对 Agent 原生"的准确表述（重要修正）**：不是"对人不友好、对 Agent 友好"，
而是**把架构的母语从"人类叙事"换成"可查询结构"**——对所有隐式知识依赖都更少。
Agent 原生红利三条：行动空间封闭（算子文法）、状态可查询（record 统一形态）、
能力可枚举（registry 自描述）。**反向警示**：间接层税对 Agent 同样成立——静态 grep
断裂处 LLM 一样靠猜；"对 Agent 原生"≠"对 Agent 免费"。

## 三、"薄"的可机械核验：M1-M6 守卫件套 + 修剪语法（判据层）

**核心论证**："还能不能再砍"这个问题之所以被反复问，是因为没有"砍够了"的可证明
信号。从灵忆实证（core.py 无"任务""会话"概念，换个 registry 就是另一个系统）反推，
"薄"有三重封闭性，各配一个行为级终审：

### 3.1 薄的定义（三重封闭 + 双绿终止条件）

| 维度 | 问的问题 | 守卫 |
|------|---------|------|
| 概念封闭 | 主干代码出现几个领域概念？ | M1 词汇封闭测试（AST 扫描标识符+字符串，对照领域词汇表命中=0） |
| 知识封闭 | 主干"知道"多少具体插片？ | M2 特判禁令（core/ 禁 if/elif 对具体 SeamType 成员分支） |
| 依赖封闭 | import 闭包指向哪里？ | M3 依赖方向契约（core 禁 import plugins//engine/，含动态 import） |
| 语义终审 | 主干能否在陌生域/全截肢下原样运转？ | M4 换域测试（合成 registry）+ M5 截肢测试（逐级 unregister） |
| 趋势仪表 | 接缝生态没人看怎么办？ | M6 接缝实现数/单实现龄期/装配 spec 环比（只观测不判对错） |

**"还能不能再砍"的机械化答案**：M4+M5 双绿即已最薄（再砍任何东西就红）；
未达双绿，红在哪砍哪。M1-M3 是"律"（静态，只触发人工审查），M4-M5 是"法"
（行为终审，不可措辞绕过），层级设计直接修复了 G10 行数红线的死因
（拿代理指标判语义问题）。

### 3.2 修剪语法（升格铁律 4）

铁律 1-3 只有生长语法（插片入册），没有修剪语法则接缝棘轮式只增不减。
用户裁决升格铁律 4，三条：

1. **接缝回收生命周期**：单实现+龄期超限的接缝进回收候选（M6 驱动），
   回收**不算主干 diff 违规**——这是"棘轮"的结构性解法（拆接缝从违例变合法事件）；
2. **违规定价（debt record）**：临时直连允许存在，但必须在 StateStore 记账
   （位置/原因/清除条件/到期时间）——债务到期自动红，"审出→入册→等待"，
   账是明账；同模块债务超额则冻结新功能先还债；
3. **审计防博弈**：静态守卫只触发审查永不自动通过，终审归行为测试；
   度量是尺子不是 KPI；仲裁问题："这让系统自描述程度变高了吗？"

### 3.3 拔插等级（L1/L2/L3 分级声明义务）

"可拔插"一词太模糊，必须分级且入册：L1 替换（J2 现行测的等级）、
L2 缺席降级（降级实现本身必须是插片，禁主干 if-else 降级）、L3 缺席裸奔。
未声明者默认按 L3 最严检验——声明义务倒逼。

## 四、守卫代码化 + CI + 台账归原语（执法层）

### 4.1 落地产物

| 产物 | 位置 | 说明 |
|------|------|------|
| M1-M5 守卫 | `tests/test_iron_law_guards.py` | 5 守卫 + 债务到期守卫（test_debts_not_expired），与旧 G1-G14 合跑 18 passed |
| 领域词汇表 | `tests/fixtures/core_vocabulary.yaml` | 70 词含中文，入册待查，变更须用户确认 |
| M6 巡检脚本 | `scripts/seam_trend_inspect.py` | 三趋势（实现分布/单实现龄期/spec 环比），快照入台账 |
| 台账 CLI | `scripts/arch_ledger.py` | debt/exemption/snapshot 全走 StateStore（data/arch_ledger/），到期债务可 query |
| CI | `.github/workflows/ci.yml` 新增 `arch-guards` job | 独立必过（守卫纯离线，不沾 unit job 的 hermetic 顾虑） |

### 4.2 M1 首扫的意外与处理

M1 首扫 94/95 个存量 core/ 文件命中领域词——**宣称概念封闭的主干，存量几乎全部
不封闭**。按项目既有"存量允许、新增即红"基线锁死模式处理：基线快照（只缩不放），
core/ 新增文件自动受检。当时把"94 文件豁免"理解为合理存量登记；**当日返审后
判定这是失守**（见第五章）——豁免登记必须走债务语法，不能整目录快照式豁免。

### 4.3 台账归原语（J4 清偿，守卫层先行）

返审发现守卫体系自己 J4 违例：豁免在 .py dict/注释里、快照在 logs/*.jsonl 里——
"状态不在可查询结构里，丢了看不见"（首轮 94 条豁免静默失败就是活证）。
清偿后：豁免 100 条 / 债务 1 条 / 快照 / 修订史 / 审查卷宗全部 StateStore record，
守卫经 `StateStore.list_keys/load` API 读账——台账换后端（json→LingYi）时守卫零改动，
兑现 docstring 的分形承诺。**守卫不是特权模块，账目与其他插片同权。**

## 五、返审循环：守卫反观守卫，铁律返审铁律

用户裁定"算子革命要先革自己的命"，返审分两波：

### 5.1 第一波（守卫反观守卫）——审出执行失守

| 失守 | 定性 | 处置 |
|------|------|------|
| M1 批量豁免 94/95 | 违反自己登记的"逐条核对"纪律 | 转债务语法追踪，豁免只缩不放 |
| 守卫不在 CI 必过路径 | 守卫存在但不守卫（复刻了"守卫真空期"） | arch-guards 独立 job |
| 豁免/债务未走 debt 记账 | 守卫作者先绕过了自己建的机制 | 台账 CLI + StateStore 归原语 |
| M6 静态口径盲区 | TOOL"单实现"是仪表假象（实际 26 实现） | 入 P2 优化任务（m6-static-only-blindspot） |
| M4 强度低于条文 | 原语级换域而非"主干测试套件级" | 如实降格表述 |

**共性根因**：建守卫时优化了"守卫能绿"而非"守卫能拦"；基线是机械抓取非逐条裁决。

### 5.2 第二波（以铁律返审铁律）——审出体系失守

用铁律条文审判铁律自身与守卫体系，最深发现：

- **铁律 3 与修剪语法文本级硬矛盾**："临时直连即违规"与"debt record 可存续"同文并存
  → 用户裁决：修剪语法升格铁律 4，铁律 3 加但书（debt 入册者为唯一例外）；
- **J4 判据对守卫体系失效一半**：豁免/债务/修订史全在 .py 注释与 jsonl 里
  → "一切真相外化为可查询结构"这条第一性陈述，对铁律体系自身曾是假的；
- **修订史不事件化**：铁律的演化不在自己的状态机上
  → 修订史 7 条 events 入册（arch_law_revision），法统可回放。

**结论（当日最重的一句）**：铁律体系还没有把自己当作第一个客户——"立法者守法
靠自觉"。清偿动作全部按铁律自己的语法执行（入册/记账/事件化），清偿本身成为
"算子革命革自己命"的实证。

### 5.3 返审的制度化（SDT-lc-006 返审触发器）

用户裁定："自身有变化审自身，外界有变化审外界，审出不法问题列入优化任务。"
落地为 `scripts/self_audit_trigger.py`：

- 八关键文件（铁律/守卫/台账/StateStore/SeamRegistry/CI/词汇表/巡检脚本）
  + HEAD 的 sha256 指纹存 `arch_audit_state`；
- 自身变化 → 守卫自检 + 债务核账 + 台账完整性；外界（台账）变化 → 新豁免/债务核账；
- 审出问题入 `arch_audit_task`（优化任务），**审出→入册→等待，不自动改码**
  （守审计权限约束：全族审计只入 .audit/ 等对方，不越权改对方）；
- 首跑即抓出上一轮遗漏的 P0（台账未入 git → CI 假红）——制度价值的第一份实证。

**提交与 P0 清偿**：commit `df48731`（117 文件）把 110+ 条台账 record、触发器、
gitignore 例外一并入库；P0 `ledger-not-committed` 关闭（关闭记录含 commit 号+验证证据，
写回 task record 可 query）。
