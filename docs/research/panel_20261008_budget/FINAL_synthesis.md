## 灵克草案被推翻的两处（如实记录）

1. **「每进程生命周期一次（reset 不恢复）」→ 错误**。AC 指出：`/budget reset` 的存在正是为了让第二次 PAUSE 发生；闩锁不重置则第二轮退化为零交接裸挂起，比第一次事故更糟。**定案：reset() 重置全部闩锁（warn 阶梯 + handover）。** 用户滥用自己 reset 是用户自己的预算，非系统风险。
2. **「白名单请求走会话续接」→ 致命缺陷**。AC：事故场景 22.7M 若按正常轮续走，遗言轮要重放全部上下文——(a)再吃一轮量级成本可能推爆；(b)极可能超模型窗口直接报错——**遗言轮恰在最需要时失效**。**定案：独立小上下文请求**（todo 清单 + 近 N 轮摘要 + 交接模板，无工具执行面），模型只产交接文本，harness 机械落盘 + 翻 relay 标记。成本从「一个满轮」降到千分位百分比。

## 实现细则（定案级）

### R1 预警注记（75% / 90% 两档）
- 判据：主维度（input_tokens/pause）比率；75% 档=**检查点档**（祈使措辞：「现在写检查点落盘」，非「你快没预算了」——AC：可验收的确定动作 > 依赖模型意愿的提醒）
- 90% 档=**交接档**（「立即收尾输出交接，下一档硬挂起且不可自动恢复」）
- 注记规范（codex）：≤40 token 短句、带机器事实（used/total、距硬挂起估算、PAUSE 后不可自动恢复）、带作用域标记 `[budget-warn, session-scoped]`、每档一次性（幂等闩锁）、最多 2 次
- 语义纪律：只要求收敛与落盘，**不得**让模型调整任务范围或自行改阈值（防行为操纵面）

### R2 遗言轮（90~100% 之间或 PAUSE 时）
- 形态：`attempt_last_rites(provider, ...)` 独立请求——messages 仅含[交接指令模板, todo摘要+近轮尾部]，**不传 tools**（写权限天然收敛为零工具执行面），产出由 harness 落盘为 LONGTASK_SOP 格式检查点 + RELAY_MARKER=waiting_relay + RESUME_HINT
- 会计：预算豁免 + 上限（≤200K input 或 1% pause 阈值取小）+ 免重试（在已超预算会话上重试=确定性失败的翻倍）
- 触发条件（AC 防滥用①）：**仅当存在激活 relay 标记或 todo 清单**（有真实交接物才给遗言轮）
- 失败兜底（AC 三层）：静默降级不重试 → PAUSE 照常 + 报告显式追加「交接未落盘，现场仅存 transcript」+ 提示捞取路径
- 红线重述（codex，防被当先例打穿）：「暂停=暂停、恢复权在用户」约束的是**任务不自动继续**，不是**状态不保存**；遗言轮不推进任务、不写业务文件、不扩权，恢复权 100% 不动

### 档位依赖关系（AC 关键洞察）
**R1 是 R2 的降级保险**：75% 档无条件外化检查点，即使遗言轮失败也只损失交接摘要质量，不丢现场。两档不是可各自否决的独立选项。
