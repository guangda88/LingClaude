## 一、起点问题：纯净 vs 能力如何平衡

### 1.1 结论：80% 同向，真对抗只在两处

本轮审计实测（前序各轮）：零调用 80% 注册面、4 个孤儿模块、4 条空壳缝——**既不提供能力也不提供纯净，清掉双赢**。真对抗仅在：

1. **边界件**：lingtongask 13 个 gate skill 类"宿主账看不见的活件"——判死活需双源数据；
2. **执法力度**：纯净执法的分寸——已定分域调档（冻结区最严锁死 / 插片红线+观察期 / 热路径免事件化白名单 / 联邦面只观测）。

### 1.2 不对称成本定则（平衡问题的理论根基）

- 纯净可瞬时达成（删了就净），能力只能累积（调用史/飞轮/经验均为时间函数）；
- **错删比错留贵**：错删损失不可逆（重建须重新积累调用史），错留损失可逆（账面噪音随时可再删）；
- 由此推出默认倾向"缓杀"——辨别框架 30 天观察期是不对称成本的机制化，不是官僚主义。

## 二、三机制咬合（辨别-执法-纠错）

### 2.1 五条机制（全部既有件升格，零新系统）

1. **数据咬合**：单一事实源（基线快照+M6 快照），三机制共用；record 三落款字段（identified_by/enforced_by/corrected_by）——不全即快照红；
2. **节奏咬合**：修剪周期=M6 快照周期，候选清单必须在 `cycle_report` 字段留归宿（回收/观察/翻案/待定四态计数），**候选消失即红**（防候选囤积）；
3. **错误传导矩阵**：辨别误杀→纠错翻案+判据修订；辨别漏判→时间自动收敛（零调用累积）；执法过宽→候选对账缺口>50% 即红；执法过严→豁免到期强制复审；纠错改坏判据→M4 换域测试兜底。**每个机制的盲区是另一个机制的主区**；
4. **权限分离**：三机制不同触发源（仪表自动/CI 门禁/用户终审），单机制闭环（自判+自收+自报）按未发生处理——ERR-01~04 事故教训的机制化；
5. **健康度仪表**：tripartite_health 四指标（cycle_report/数据新鲜度/传导完整度/权限分离度），**长期全绿本身是纠错通道死亡信号**。

### 2.2 业界对标（证据等级分层）

| lc 机制 | 业界最接近物 | 证据 |
|---|---|---|
| 数据咬合 | SLO 文档单一事实源（sre.google Error Budget Policy ✅直证） | 同构 |
| 节奏咬合 | GitLab 月度 Error Budget Report（每月 4 日公开 ✅直证） | lc 缺 cycle_report 实装（后已补，见 §五） |
| 错误传导 | postmortem 必产 P0 action item 强制回写（✅直证） | lc 缺"翻案强制归因"机制化（已列入建议） |
| 权限分离 | SOC2 审计师独立（⚠带限） | lc 外部评审已跑一轮未常态化 |
| 理论根基 | 控制论：反馈回路闭合+延迟有界+控制器带宽覆盖变化率（⚠带限） | "插片区净减"判据的理论根据 |

**业界最锋利警告**（✅直证）："SLO without policy = reporting metric, not decision tool"——有辨别无执法，仪表变摆设。lc 空壳缝/零调用模块的根因即此。

## 三、绞杀者模式（重构 vs 重写的第三条路）

### 3.1 重构 vs 重写的判定（✅实测数据支撑）

- **重构更难**（三战场同时作战：活系统连续性/账目同步/暗依赖排雷 vs 重写的一个战场）；
- **但重写丢三大资产**：62K 行测试/267 测试文件的守卫网、已验证的 2.9K 主干雏形、已付学费的守卫体系——重写省的难度会在守卫真空期加倍偿还（seL4：可信度是随验证累积的资产，不可复制只能续写）；
- **判定**：走绞杀者模式（Strangler Fig），不做大爆炸也不推倒。

### 3.2 四道闸门（机制保障，全部既有件升格，合计 1-2 天）

1. **单向棘轮状态机**：红名单件 core→migrated→removed 只进不退；reverted 须挂 ERR 案号，无案号回退=守卫红（ratchet-001 已有雏形）；
2. **双轨互斥显式化**：同一符号 core/plugins 双存时必须声明谁服务流量、另一个标 superseded，禁隐式双活（ERR-05 期间五桥双副本是反面教材）；
3. **逐族冒烟门禁**：迁移类 commit 强制三验（import 链/CLI 入口/族内回归）进 lefthook——"汇报必附实测"从人检升机检；
4. **终局条件**：红名单清零硬期限（建议 2026-12-31，11 族 / ~13 周）+ 完成即 M3 阶段 3 自动启用（锁死防复发）。

### 3.3 实战验证

ERR-05 事故（d36e5b9 迁移误删 session_token_sink 致启动链崩溃）恰好实证了闸门 3 的必要性：**单测 28 passed 绿而 CLI 全死**——v1 修复方案被 M3 守卫正确拦截（拦截能力实测有效），v2 方案（五桥恢复回 core/）过四道门。闸门不是理论设计，是已发生事故的机制化回应。

### 4.2 进化形态定性（用户裁定，修正本文档 v1 的两处误判）

- **任务导向进化（task-driven evolution）**：任务召唤生长（"遇到什么任务，就长出完成这个任务的能力来"），用户只在"接不接任务"上选择。实证：本轮全部能力（sub_agent 激活/三机制咬合/tripartite 重建）均为具体任务召唤而生；唯一反面教材恰是建闸期"预想未来需要"的预浇筑（全成死件/空壳）；
- **L0 也是插件**：必填缝（槽位不可空）但**实现可变**——教义存身之所今天住 git 保护分支，明天可以是签名服务/联邦共识；**连"如何进化"的规则本身都在进化范围内**。唯一不变量：2T3A 状态机主干。修正 v1 "宪法性限制/教义内容冻结"的误判——限制的是单次 transition 的合法性（任何 L0 变更也须 record/transition 留痕），不是进化范围；
- **自纠错已实证**：ERR-01~04 的发现路径是模型自核验（git log/ls/pytest）暴露，非用户人工查账——**错误检测已自主化**；错误处置仍共同裁决（用户终审），处置自主化是未来任务，按辨别框架四判据随纠错史可信度自然下放。

### 4.4 五条可借鉴（按价值排序）

1. **轻回收/archive 休眠**（DGM stepping stone）：回收分两档——轻回收（撤运行时+attic 归档+dormant 标记，可复活）/重回收（删，须技术债理由）。**化解纯净/能力剩余张力：运行时纯净+期权保留**。首例泛化：TRANSPORT 复活条款标准化；
2. **显式 fitness 字段**（AlphaEvolve evaluator）：M6 快照加 fitness 字段（工具=成功率+耗时/迁移=红名单减项/辨别=误杀率），第三类判定升级为"分数低于阈值"；
3. **EVOLVE-BLOCK 圈定**（AlphaEvolve）：可自改插片内设进化锚点，block 外冻结执法——M1 粒度从文件级细化到块级；
4. **观察期多样性保留**（DGM 开放式探索）：任务类型分布漂移超阈值→观察期重置，防修剪杀死"还没等到任务"的期权；
5. **自进化变更强制走 worktree**：worktree.py 已有，缺一条守卫规则。

## 六、最终结论（经用户两轮纠正后的定稿）

**lc 是当前唯一把"任务导向进化"机制化到可运行程度的架构：任务召唤生长（插片）、四判据修剪（辨别）、守卫拦截（执法）、自核验纠错（ERR 五案实证）、连进化规则本身都在进化范围内（L0 可变）——唯一的不变量是 2T3A 状态机主干，唯一的未决项是处置自主化的时机（由纠错史可信度按辨别框架四判据决定，机制已备，无需新造）。**

下一步不是补机制，是让飞轮数据继续积累、让修剪周期跑起来、让处置建议权在数据充分时自然下放。
