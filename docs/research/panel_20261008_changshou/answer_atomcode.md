# 《与长寿智能人谈天》H5 产品完整详细方案
> AtomCode 独立调研成稿（2026-10-08）。定位：H5 交互式 AI 口述回忆录，面向长者，聊天式采集人生故事，自动整理为结构化回忆录；时间轴锚定"智能气功发展大事记"语料库；TTS 采用用户本人音色克隆。

## 0. 项目定位与目标（一句话）
"先听他讲，再与他谈"：以长者口述为第一公民，产出可编辑、可追溯、可导出的结构化回忆录（听他讲）；在语料库基础上提供基于智能气功大事记的可溯源问答（与智能人谈天）。双模式共享同一记忆中枢与同一时间轴，谈天中涌现的个人记忆可回流时间线。

### 1.2 五条可迁移结论
1. **防幻觉是行业第一红线**：清诺谛听早期把"同村某人被枪毙"写成"丈夫被枪毙"；小智回忆录把"只用讲过的"写进产品文案。→ 本项目 Scribe/SectionWriter 必须有硬性"来源标注+待核实"标签。
2. **真人触点不可省**：kimi 版记录软件测试期老人"不喜欢对冷屏自言自语"、频降→改 AI 辅助真人采访。→ 产品保留"家属共访/志愿者结对"入口，H5 是辅助而非替代。
3. **持久性必须被设计出来**：HereAfter 关停后数据取不回。→ 一键导出（录音+文字+记忆卡+成稿）、数据可携、开源格式优先。
4. **问题清单标准化有效**：StoryCorps 证明固定题库+个性化生成是可靠骨架；智能气功大事记天然提供"时代锚点题库"。
5. **双入口（语音+文字）与方言 ASR** 是所有存活产品的标配。

## 2. 对四份参考材料的仲裁

### 2.1 分歧点与裁定
| 分歧 | 各版立场 | 裁定（AtomCode） | 理由 |
|---|---|---|---|
| IMA 直连读写 vs 本地 RAG 主存 | deepseek 版声称可"上传 IMA 当存储"；kimi 版实测 OpenAPI **只增查、不改删、不导出**；豆包版建议优先 IMA | **本地 RAG 为主存，IMA 降级为"只读知识源+多备份之一"** | IMA 边界使"记忆卡人工编辑、误删找回、批量导出"全部不成立；主存必须在本地。IMA 的价值在 496 条混元灵通语料的现成可读 RAG，用 OpenAPI search 读；"万能导"导出重建 MD 作为灾难恢复路径 |
| 知识库三选 | 豆包：IMA 优先；qwen：IMA 五星；kimi：本地 RAG 推荐 | 同 2.1 第一条，另加 **Obsidian 本地库为编辑态载体**（双链+git 版本化），飞书多维表作家属协同视图（可选） | 主存/编辑/协同三层分离，单一平台不构成单点 |
| 单模式 vs 双模式 | kimi 版提出 A"听他说"+B"与智能人谈天"；其余版默认单模式 | **采纳双模式，但 B 是 A 的增值而非平行入口** | 项目名即含"与智能人谈天"；但 HereAfter 教训+老人使用数据表明记录型主路径留存更高。B 模式只在 A 沉淀出足够个人记忆+语料库语料后解锁深度问答，避免"冷冰冰的屏幕自言自语" |
| 记忆架构 | deepseek 四层（ChromaDB+结构化表）；豆包单张记忆卡 YAML；qwen 三层滑窗 | **豆包 schema 为原子 + qwen 三层为生命周期 + deepseek 检索独立于 LLM** | 记忆卡（ID/年代/地点/人物/事件/原话/情绪/主题）是数据模型；瞬时→短期摘要→长期向量是存取策略；SMILE 式检索独立检索管线不塞进对话 prompt |
| 模型路由 | 各版模型 ID 全带未验证标记 | **见 §6：能力分级路由而非点名路由** | 免费模型时效性最强，点名模型 ID 会过期；只定"flash 级/长上下文级/本地兜底"三档，清单实时核验 |
| TTS | 各版多写"温暖中老年声线" | **用户本人音色克隆**（任务硬性要求） | 长辈听自己的声音念自己的回忆录，情感价值+适老化双收益；成本与合规见 §5 |

### 2.2 四份材料各自的盲区（批判性参考结论）
- deepseek 版：把 IMA 当可写存储——与 kimi 实测的"只增查"矛盾，采信实测；模型 ID 全未验证；没谈 IMA 配额与关停下数据可携性。
- 豆包版：最工程化但偏保守，未谈音色克隆与双模式；"免费层每日 100 次"未验证。
- kimi 版：唯一带 IMA 实测边界与 HereAfter 教训的，本方案骨架多取自它；弱点是预算估算（300-500 元/年服务器）未含 ASR/TTS 音色克隆成本。
- qwen 版：市场数据（60%/3%/6800万/5-30万）全部未验证，只可作方向性背景，不可引用进对外文案；商业模式最完整，适合 P3 阶段参考。
- 共同盲区：都没有把"智能气功发展大事记"作为**时代锚点题库**来设计——这是本项目区别于所有竞品的语料资产，§3.4 专门设计。

## 3. 产品定义

### 3.1 用户与场景
- 主用户：60+ 长者（讲述人），可带子女协同；
- 次用户：子女/家属（协同补证、阅读、下载成书）；
- 场景：家中/养老机构，手机 H5 免安装，单次 20-25 分钟会话（豆包版时长管控，行业共识），疲惫自动建议休息。

### 3.2 功能边界
做：口述采集（语音/文字）、防幻觉回忆录生成、可编辑记忆卡、大事记时间轴问答（模式 B）、本人音色 TTS 朗读成稿、一键导出（PDF/EPUB/录音包/Markdown）。
不做：医疗宣称（养生功法内容只呈现不诊断，见 §7）、已故亲人拟人模拟（合规禁区）、付费数字永生营销。

### 3.3 双模式定义
- 模式 A「听他讲」（默认主路径）：固定题库引导（由大事记时代锚点生成）→ 聊天追问 → 记忆卡抽取 → 章节组装 → 成稿/成书。
- 模式 B「与智能人谈天」：基于智能气功大事记语料库 + 个人记忆卡的混合 RAG 问答；**每条回答带出处标注（语料章节/记忆卡 ID），无匹配即婉拒不编造**（HereAfter 规则）；谈天中识别出的新个人记忆回流时间线（标记"谈天涌现"待核实）。

### 3.4 大事记语料的时间轴设计（本项目独有）
- 语料源：ZhinnengBooks/Literature 仓库 `1.文本`（1.教材/2.专著/3.杂志/4.其他/README.md/校对凡例.md，已实测存在）。
- 构建：从语料抽取**年-事件-人物**三元组 → 大事记时间轴 JSON（年份/事件/关键词/出处），双用途：① 模式 A 提问骨架（"您 19XX 年参加过 XX 活动吗？"把抽象提问变具体时代锚点）；② 模式 B 检索索引。
- 时间线展示：长者口述事件落在大事记轴上，形成"个人史 × 气功发展史"双轴回忆录——这是与全部竞品的核心差异点。

## 4. 系统架构
```
[H5 前端] Vue3/Vant4(中文生态) | 大字体≥16pt | 按钮≥44pt | 语音按住说(Web Audio/MediaRecorder)
      │
[后端] FastAPI（会话编排/ASR-TTS 网关/记忆卡 CRUD/导出器/模型路由）
      │
[能力层] ASR: 云端带方言 ASR（腾讯云/通义听悟类，二选一核验）
         TTS: 本人音色克隆（cosyvoice/火山 类，二选一核验，见 §5）
         LLM: 分级路由池（§6），统一 OpenAI 兼容接口
[记忆层] 主存=本地：SQLite(记忆卡表)+向量库(首版 FAISS，pgvector 升级)+Obsidian MD(编辑态,git 版本化)
         知识源=只读：IMA OpenAPI search(混元灵通 496 条)+ZhinnengBooks 大事记语料
[备份] 录音本地+云双备份；每周快照；导出工具链常驻
```
部署：单台云服务器（Linux）+ 静态 H5；H5 域名 ICP 备案（kimi 版合规要求，正确）。

## 5. 语音方案（含本人音色克隆落地路径）
1. 采集：H5 MediaRecorder 录音，断点续传，原始音频先落盘再解析（外部结果解析纪律：成功判定对照真实响应结构，禁止假设字段路径）。
2. ASR：方言/口音是刚需（行业共识），选云端带方言 ASR 服务商；两家 API 能力与费率**需实时核验**后再定，不预设。
3. 音色克隆：用户 3-10 分钟样本（录音本身即是样本来源）→ 服务商 zero-shot 音色合成（volcano/cosyvoice 类，具体端点**未验证需核验**）→ 成稿用"他本人的声音"朗读。注意：样本属个人生物特征信息，个保法下需单独同意+最小化保留；样本与合成件默认私有、随账户注销删除。
4. 降级链：音色克隆失败 → 温暖中性声线 → 纯文本朗读（微信/系统 TTS），功能不中断。

## 6. 模型选型与路由（能力分级制）
- 三档池（只定档位不定 ID，**所有具体模型 ID 引用均为"需实时核验"**，因免费池清单时效性强）：
  - 日常谈天/轻量抽取：flash 级（Zen/OpenRouter 免费池轮换；本工作区既有 6h 同步脚本 `sync_opencode_client_models.py` 可直接复用做模型清单同步，"只增不删"策略）；
  - 章节写作/矛盾检测：长上下文级（≥128K 档位）；
  - 兜底：本地 Ollama 中等规模模型+结果缓存+队列（kimi 版建议，正确）。
- 路由规则：任务标签映射档位；免费池掉档自动降档不断流；**隐私通道分界（kimi 版设计，采纳）：家庭口述内容走本地/零保留通道，仅语料库公开内容走免费通道**——部分免费模型可能用数据训练，这是不可省略的设计。
- OpenCode-Zen 端点与 OpenRouter 端点为任务给定事实，可用；两家免费配额**未验证**。

## 7. 数据与隐私合规
- 个保法：最小必要、单独同意（生物特征音色样本）、就近存储；注销即删（HereAfter 教训）+ 一键全量导出（录音+文字+记忆卡+成稿+大事记轴 JSON）。
- 内容合规：涉养生/功法内容**不得做医疗宣称**，成稿模板内置免责声明+人工复审位；AI 生成章节标注"AI 辅助整理，待核实"，年代人名走家属交叉验证流程。
- 拟人化互动边界：deepseek 版引用的《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）**未验证**，条文内容一律按"待核验"处理；稳妥原则：不做已故亲属模拟、健康使用提示常驻、伦理审查清单随版发布。
- 跨境：若走境外免费模型端点，口述数据出境需评估；方案主链路默认全境内（本地+IMA 境内+境内云 ASR），免费模型池仅处理公开语料。

## 9. Agent 拆分（职责边界清晰版）
| Agent | 职责 | 硬规则 |
|---|---|---|
| Interviewer（访谈） | 追问/情绪承接/单问题原则 | 不纠正、不辩论、不编造；每轮只问一个问题 |
| Scribe（记录） | 口述→记忆卡（§schema 见 §10） | 只用讲过的内容；出处字段必填 |
| Planner（规划） | 叙事空白/矛盾检测/下次会话建议 | 矛盾标"待核实"不静默改写 |
| SectionWriter（成稿） | 时间线编排+章节写作 | 保留原话引用块；AI 润色与原话分层展示 |
| ChatKeeper（模式 B） | 语料+个人记忆混合问答 | 无匹配婉拒；答案带出处；新记忆回流标记 |

## 10. 记忆/知识库设计
- 记忆卡 schema（采纳豆包版 YAML 字段，扩展）：memory_id / session_ts / inferred_era / location / people[] / event_summary / verbatim_quote / emotion_tag / topic_tags / source_type(口述|谈天涌现|家属补证) / verified(待核实|已核) / 可编辑。
- 生命周期（qwen 三层）：瞬时=当前会话窗口；短期=近 5-10 轮摘要；长期=向量库+SQLite 双写；检索管线独立（SMILE 式，deepseek 版），每次对话前召回 3-5 条注入。
- 知识库分层：L0 语料库（ZhinnengBooks 大事记 + IMA 混元灵通只读）；L1 个人记忆（主存本地）；L2 编辑态（Obsidian MD，git 版本化，家属可见快照）。
- IMA 边界（kimi 实测，采信）：只增查、无改删导出；"万能导"导出 MD 建双备份；成员加入确认流程先行。

## 11. 风险清单（Top 10，含缓解）
1. 免费模型下架/配额波动（高）→ 多供应商路由+本地兜底+模型清单 6h 自动同步（复用 SDT-lc-007 脚本思路）。
2. 口述内容误流入会训练的免费通道（高）→ 隐私通道分界为架构硬约束，CI 断言校验。
3. 老人留存低/冷屏自言自语（中-高）→ 家属共访、真人志愿者结对（kimi 版：唯一可持续形态）。
4. 幻觉编造（高）→ 来源标注+待核实+人工复审位（§2.1 结论 1）。
5. 方言 ASR 准确率（中）→ 双服务商 A/B+口述原文回听核对入口。
6. 音色克隆合规（中）→ 生物特征单独同意、最小化保留、注销即删。
7. 功法内容医疗宣称越线（中）→ 审核中台+免责声明模板+人工复审。
8. IMA 权限被拒/政策变动（中）→ 本地 RAG 主存+飞书/Obsidian 双备份（kimi 版）。
9. 拟人化新规细则未明（中）→ 条文未验证前按最严口径：不模拟已故亲属、健康提示常驻。
