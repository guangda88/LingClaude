## 一、为什么是这三本书

三本书回答三个不同层面的问题，正好构成 lingclaude 自优化的完整方法论：

| 书 | 回答的问题 | 在系统里的位置 |
|---|---|---|
| 钱学森《工程控制论》 | 一个**单回路**怎么稳定收敛？（在不完全已知、干扰不可避免、元件不完全可靠的条件下） | **内环**——每条纠错回路的设计纪律 |
| Meadows《系统之美》 | 该动**哪里**？为什么动了参数没用？ | **结构**——回路盘点、陷阱识别、杠杆点排序 |
| Kelly《失控》 | 怎么让系统**自己**变好而不是被谁变好？ | **外环**——去中心化、涌现、控制权分配 |

lingclaude 的独特赌注（CHARTER：自优化是核心能力）恰好押在这三本书的交集上——
但目前机制大多"有形无实"（见 §二），本亡羊补牢的代价远小于继续裸奔。

## 二、lingclaude 系统解剖（控制论视角）

### 2.1 已有回路清单（传感器 → 决策 → 执行器）

| 回路 | 传感器 | 决策 | 执行器 | 实际状态（2026-09-01 实测） |

### 2.2 摩擦力台账（本会话实证，按三书术语命名）

摩擦 = 单位有效产出之外的额外代价（返工、等待、噪声、无效常驻）。以下是本会话
亲眼所见、可复现的摩擦源——每条标注病理：

| 实证 | 病理命名 | 出处 |
|---|---|---|
| F12c `_load_keys_env` 定义了但零调用，审计总账标 ✅ | **开环申报**（完成-验证之间无传感器） | 钱学森：反馈是应对不确定性的唯一手段；无反馈=盲飞 |
| 审计报告称 doc_consistency ✓ 而检查器实际红 | **双传感器打架无仲裁**（账目与仪表盘冲突时账目赢了） | Meadows L6：信息没有送到有说服力的位置 |
| e2e mock 掉 `call_tool` 使 BusResponder 断链测试全绿 | **规则规避（rule beating）**：绿测试成了目的本身 | Meadows 陷阱；Goodhart |
| e2e 靠 `LINGCLAUDE_RAISE_EOF=1` 逃生门绕过挂死 | 同上——测的是地图不是地盘 | 同上 |
| Esc 监听线程永生堆积、抢 stdin | **执行器无关闭**（增强无平衡回路） | 钱学森：反馈可致自激振荡，须有停机条件 |
| 守卫 14→16 涨了没人同步 11 处文档，检查器红着没人看 | **信息延迟**（传感与执行之间隔了一个"下次再说"） | Meadows：延迟致振荡 |
| BusResponder 在单轮进程也启动、被硬杀 | **无效子系统常驻**（无目标的流量） | Kelly：.parts 要有存在理由 |
| 索引性能阈值 5s→120s（commit e217597，沙箱适配） | **漂移到低性能**的临界案例（有正当理由的放宽也该留衰减记录） | Meadows 陷阱 4 |
| 规则库"从未删过一条"（灵研原话） | **增强回路无平衡**：规则只增不减，摩擦单调上涨 | Meadows 增强回路；Kelly 九律之"不求最优" |
| 2026-09-06 黑名单 `apt`/`at` 子串误伤合法命令（`pytest --capture`、`cat VERSION` 被拦） | **规则规避的反向（rule beating inverse）**：规则越严 → 合法用例越绕 → agent 解释绕路方案 token 越涨 → 安全规则反成摩擦源 | Meadows：追逐错误目标的镜像；钟表域原则要求"匹配应当是确定性的" |
| 2026-09-06 用户输入 518 万 / 输出 22 万 = **输出比 4.2%**（正常 1-2%） | **会话层 token 放大回路**：单次熔断 → agent 重新读代码 + 解释方案 + 重连 → 输出涨 3-5×；多次熔断叠加导致输出/输入比失衡 | Kelly：钟表域/蜂群域分界不清时，精确任务被蜂群反复扰动；钱学森：执行器应单击收口而非反复抖动 |

### 2.3 总诊断（一句话）

**lingclaude 不缺回路设计，缺的是回路的"合闸"**——传感器、决策、执行器三类
零件都在，但关键几条回路长期断路（daemon 5 个月没转、声明与验证脱钩、红灯
不拦截）。融入三书思想的重点不是发明新机制，是给已有回路通电+装保险。

### 2.4 一个具体的 token 消耗放大案例（2026-09-06 用户现场报）

现象：单次会话输入 518 万 / 输出 22 万 token，输出比 4.2%（正常 1-2%）。逐字归因：

1. **第一推力（黑名单误伤）**——`pytest --capture=fd` 进栈后被 `apt` 黑名单拦
   下（子串匹配，无词边界）。我必须：(a) 解释为什么合法命令被拦；(b) 提议
   改命令绕路；(c) 解释为什么不绕过安全；(d) 重写 prompt 让模型再生成
   替代命令。**4 次循环就消耗了绕路所需的 token。**
2. **第二推力（流式超时反复）**——每次熔断后流断点丢失，下轮必须把上下文
   重新编码进新命令——输入 token 也同步涨。
3. **第三推力（执行器反复抖动）**——按钱学森诊断，**执行器应单击收口**而非
   反复抖动。`lingclaude run -i` 的多轮循环本是为复杂任务设计，却被
   单步命令调用，触发"试→错→重试"的反复执行。

**系统论对应**：
- 黑名单误伤 = **规则规避的反向**——安全规则越严，合法用例越绕，token 越涨
  （Meadows：追逐错误目标的镜像）
- 反复重试 = **执行器缺单击收口**（钱学森：每条纠错回路必带增益上限）
- `run -i` 多轮循环被滥用 = **钟表/蜂群域未分**（Kelly：精确任务交给钟表模块）

**对应修复（已落地）**：
- 黑名单统一词边界匹配（`5396035` + `6ab877e`）：`pytest --capture`、`cat VERSION` 不再被拦
- 单步命令首选 `lingclaude run "task"` 单轮模式，而非 `run -i` 多轮

**对应路线（待做）**：
- R7：CLI 单轮入口捷径（`lingclaude ask "task"`），绕流式会话减少 token 堆积
- R8：执行器单击收口（流式熔断后**不立即重连**，让会话终止让用户决定）

## 三、框架提取

### 3.1 钱学森《工程控制论》——内环纪律

**1. 工程控制论的分野**：只研究"对设计受控系统有直接工程应用"的部分——在
被控对象不完全已知、扰动不可避免、元件不完全可靠条件下做设计。**LLM 正是
"内部不可观、模型不完全"的被控对象**，harness 必须按工程路径而非先建模完备
再控制的路径设计。

**2. 反馈是应对不确定性的唯一手段，但有代价**：测误差→施校正的闭环可以压制
不确定性，然而增益×迟滞会引发自激振荡。推论：**一切纠错回路必须带增益上限、
限幅与停机条件**。lingclaude 对应：H2（同工具 3 次同果即停）、H15（3 连败熔断）、
F12f 同回合仅重试 1 次——这些就是"限幅"，应作为所有新回路的标配审查项。

**3. 稳定性要设计期判定，不靠运行期试错**：Routh/Nyquist 判据把"会不会发散"
变成上线前可回答的问题。工程化类比：**纠错幅度×对象敏感度>1 即发散**——
改 config 阈值的 daemon 执行器（一次调多参数、无复测）天然有此风险。

**4. 过渡过程与稳态同等重要**：评价系统不只看稳态误差，还看超调、振荡次数、
收敛时间。对应：**agent 被纠正后的恢复过程**应以「corrections 之后多少回合内
frustration 回落」度量，而非只看终态通过——`behavior_trend()`（本轮新增）
提供了分子分母。

**5. 镇定与随动分离**：抗扰保持设定值（regulation）与跟踪变化目标（servo）是
两类回路，指标不同。lingclaude 已有正确分形：**治理回路管不变量**（安全规则、
H8 危险操作预审、敏感路径门——镇定），**TaskRouter 跟随任务意图**（随动）。
后续新增机制时须先声明属于哪类，防止用随动回路改不变量。

**6. 用不十分可靠的元件做出非常可靠的系统**（可靠性来自结构而非元件）：provider
waterfall 换候选、多 provider 兜底、LACP 多 transport——方向正确；缺的是对
**降级路径本身的演练**（已列审计遗留：BusResponder 真执行链）。

**7. 综合集成法（metasynthesis）**：专家定性评审 + 机器定量测试，多轮迭代从
定性到定量。对应 lingclaude 已有的「灵族评审 + AST 评估器 + pytest」三件套——
本文件本身即一次 metasynthesis 实践（定性理论 → 定量落点）。**差距在迭代次数**：
评审与评测是一次性串联而非循环。

**8. 开放复杂巨系统（OCGS）**：子系统巨多、开放、演化——不能纯还原（丢涌现）
也不能纯整体（无定量）。灵族多 agent + 工具生态正是 OCGS；总体设计部思想 =
需要一个常设"集成视角"角色，当前由审计担当（灵克）兼任。

### 3.2 Meadows《系统之美》——结构与杠杆

**基础件**：存量（accumulation，有惯性=系统记忆）/流量（变化率）；调节回路
（balancing，恒温器）/增强回路（reinforcing，复利）；**延迟**（反馈延迟造成
振荡——要害不是消除延迟，而是让变化速率慢到延迟能跟上）；系统三韧性来源：
resilience / self-organization / hierarchy。

**陷阱对照表**（识别信号 → lingclaude 现状）：

| 陷阱 | 识别信号 | lingclaude 实例 |
|---|---|---|
| 规则规避 rule beating | 指标达标、目的落空 | mock 全绿掩盖断链；逃生门 env |
| 追逐错误目标 | 分数漂亮、体验差 | 「测试通过」≈「功能可用」的隐式等号 |
| 转嫁负担 | 快修越多、自愈越弱 | 事故靠族长人肉救（git clean 后重建） |
| 漂移到低性能 | 基线悄悄降 | 阈值放宽无衰减复核记录 |
| 政策阻力 | 越修越弹回 | 多成员并行改同一工作区，互相撤销 |
| 增长极限 | 投入加倍产出不加倍 | 测试数涨到 2167 而开箱体验（webUI 401/CLI 挂死）未同步涨 |

**12 杠杆点映射到 lingclaude**（强→弱）：

| 杠杆 | lingclaude 对应物 | 现状 | 判断 |
|---|---|---|---|
| 2 范式 | CHARTER「自优化是核心能力」 | 写在纸上，机制未合闸（daemon 5 个月 1 转） | **范式与实践的落差本身是最大病灶** |
| 3 目标 | 「绿测试」vs「真实可用」 | 目标置换正在发生（见陷阱表） | 需在 PRINCIPLES 显式重申（本轮已做 §十） |
| 4 自组织 | learner 规则提取、known_unknowns、H4 权限 | 有，但缺护栏与复核 | 保留，加衰减复核 |
| 5 规则 | lefthook + linggit 20 checks + AST 门 | 有 | 是最划算的强制层 |
| 6 信息结构 | H17 闭环申报（本轮新增）+ 审计总账自动注入 | **本轮落地** | 最廉价高杠杆：把验证证据放到声明完成的那个位置 |
| 7 增强回路增益 | 规则只增不减；成功 provider 更健康 | 前者无平衡 | 规则库需要衰减回路（复用 layered_memory 艾宾浩斯思想） |
| 8 调节回路强度 | daemon 循环 | 断路 | 让它周期化、report-only 默认 |
| 9 延迟 | 守卫触发→报告；文档同步 | 均有人工延迟 | 「当场同步」纪律（doc_check 进 pre-commit） |
| 10-12 结构/缓冲/参数 | 上下文预算、阈值、温度 | 调参吸引 99% 注意 | **明确降级为最后手段** |

**有限理性推论（Meadows 最实用的一条）**：每个 agent 只根据手头局部、延迟、
失真的信息做合理决策 → **把缺失的信息以有说服力的形式送到正确的位置就是高杠杆**
（电表装门厅，用电降 30%）。H17 的本质就是一只"装在门厅的电表"。

### 3.3 Kelly《失控》——去中心化与涌现

**1. 九律（Nine Laws of God）**：分布式存在 / 自下而上控制 / 培育报酬递增 /
靠组块生长 / 最大化边缘 / 尊重错误 / 不求最优多目标 / 追求持久的不均衡 /
变自生变。逐条对照：PRINCIPLES §二「先跑通再优化」= 组块生长（已有）；多
provider 生态 = 最大化边缘；TaskRouter 多候选 = 不求最优；learner 规则提取 +
治理提案改原则 = 变自生变（有通道，缺周期）。

**2. 蜂群的成立与失效条件**：成立=无中央控制、子单元自主、高连接、非线性相互
因果（LingBus 5 成员对等网符合）；**失效=延迟**——5000 人群体能玩 Pong 却
降落不了飞机，杆到效果的长延迟使群体陷入过度补偿震荡。**推论：群体智能擅
适应，不擅精确与危险时刻**——所以 H8 危险操作不能靠蜂群涌现，必须走钟表式
窄域模块（敏感路径门/沙箱/命令黑名单=PRINCIPLES §九）。Kelly 的术语：
*clockware vs swarmware*——多数任务是半钟表半蜂群的混合体，关键是分清哪半。

**3. co-control（共同控制）**：人不做被动监控者（人极不擅长），机器包住安全
边界，人在战略点"放牧"机器。H8 广播意图+30 秒反对窗口正是 co-control 原型；
族长/审计担当的角色是骑手不是舵手。

**4. 涌现只能被运行出来**："运行系统是发现其中涌现结构的最快、最短且唯一
可靠的方法"。高层的复杂性无法从低层推出——**评测不能替代实跑**。

**5. 世界即通信总线**：agent 间少发消息，多读他人行动造成的外部状态变化，
容忍丢包。**git 工作区就是灵族的共享世界**——本会话两次被并发提交扫走改动，
正是"只发消息不读世界"的摩擦实证；对策是 commit 前后互读 status（见 R6）。

**6. 错误是资产**：网络"容纳而非清除错误，靠小失败防止大失败"。沙箱+回滚+
`known_unknowns` 声明（承认未知）都是正确方向；要把失败率当**探索预算**管理
而不是当纯损失压制。

**7. 前车之鉴（1959 自组织研究衰亡）**：控制论死于"得不到实时实验回路"——
**没有可运行实验回路的理论会干腐而死**。daemon 断路 5 个月就是 lingclaude
版的干腐前兆；本文件的 R2（回路周期化）是对这条死因的直接防御。

**8. 记忆即知觉**：分布式记忆中回忆=从散落线索重新拼装一次知觉（而非存档
回放）。layered_memory 的艾宾浩斯衰减+ExperienceStore 检索方向一致——记忆
系统的健康指标应是"重构命中率"而非"存量大小"。

## 附录 B：R6 工作区并发纪律（本会话两次实证的制度化）

工具：`scripts/prechange_snapshot.py record|check` —— 把 `git status/diffstat/HEAD`
快照进 `.lingclaude/workspace_watch.json`，HEAD 未动而工作区变化 = 并发改动信号。
**自动化接线**：lefthook pre-commit 已挂 `workspace-snapshot`（提交前留基线，advisory）。
**冲突记录**：不接 post-commit——`.git/hooks/post-commit` 已被灵字辈钩子 v3.0
（提交后审计签名验证）占用且其源不在本仓库，lefthook 接管会覆盖族级资产；如需
post-commit 基线，须与灵字辈协调链式调用。
