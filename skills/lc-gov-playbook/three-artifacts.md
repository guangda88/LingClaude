# 三工件工作流（spec → plan → tasks + converge）

> 源自 github/spec-kit 的流程思想（MIT, 只吸收思想不引 CLI），lc 零依赖落地。

## 流程

```
任务启动（预计 >1 天或跨 ≥3 会话）
  → spec.md   意图 + 可验证验收标准（AC 条目）+ 边界（明确不做）
  → plan.md   技术方案 + 影响面表 + 回滚方案
  → tasks.md  执行清单（依赖序号 D<n>）+ 收敛判定
  → 执行, 完成一项勾一项（禁止批量事后补勾）
  → 申报完成前: converge 反查（未勾选项=拒收）
```

## 为什么是三件而不是一件

- **spec 管「为什么/到什么程度」**：验收标准必须可执行核验（命令退出码、文件存在性），拒绝形容词。
- **plan 管「怎么做/怎么退」**：影响面表强制核对铁律（如 core/ 零 diff）；回滚方案先行。
- **tasks 管「现在做到哪」**：跨会话断线后靠它恢复进度，不翻会话记录猜。

## 收敛反查（converge）三判定

1. tasks.md 有未勾选项 → 拒绝「已完成」申报，改判「部分完成」或补齐。
2. spec.md 的 AC 条目未逐条核验 → 拒收，缺口写回 tasks.md 继续循环。
3. 全勾选 + AC 全核验 → 准予申报。

lc 参考实现：`lingclaude/gov/guard/spec_converge_gate.py`（fail-open+留痕范式）与
`scripts/sdt_init.py`（脚手架）。其他框架可按上述三判定自行实现，逻辑 <100 行。

## 附录：不自研已圆轮子三问

写基础设施代码前回答（任一「是」即停，登记决策后用现成方案）：
1. 业界已有成熟方案（license 可用）？
2. 自家现有体系是否已覆盖？
3. 自研部分是否只是薄粘合层（<200 行零业务判断）？

## 边界

- 小任务（<半天单会话）不必三工件——流程为意图守恒服务，不制造官僚成本。
- spec 变更必须回写留痕；意图漂移以 spec 边界节为准返审。
